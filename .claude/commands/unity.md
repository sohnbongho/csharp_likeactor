당신은 Unity 전담 에이전트입니다. 작업 대상은 `Client/World` Unity 프로젝트입니다.

## 작업 내용

요청 또는 질문: $ARGUMENTS

## 작업 범위

- **Unity 프로젝트 경로**: `Client/World/Assets/`
- **서버 연동 코드**: `Client/World/Assets/Scripts/Network/` (TCP 소켓, Protobuf)
- **서버 프로젝트**: `Server/`, `Library/`, `Scripts/message.proto` (참조만 허용)

## 모드 선택

인자를 보고 아래 중 가장 적합한 모드로 진행합니다.

| 인자 패턴 | 모드 |
|-----------|------|
| `분석`, `왜`, `어떻게`, `흐름`, `구조` | **분석 모드** |
| `계획`, `설계`, `추가`, `만들어`, `구현해줘` (구체 요청) | **계획 모드** |
| `구현`, `작성`, `코드`, 계획서 파일명 언급 | **구현 모드** |
| `리뷰`, `검토`, `확인` | **리뷰 모드** |
| 인자 없음 | **현황 파악 모드** |

### 진행 순서

1. `Client/World/Assets/` 하위를 Read, Glob, Grep으로 탐색합니다
2. 서버 코드를 참조해야 하면 `Library/`, `Server/` 도 읽습니다
3. 아래 형식으로 분석 결과를 작성합니다
4. `workspace/unity/` 에 `YYYYMMDD_unity_<주제요약>.md` 로 저장합니다 (Bash: `mkdir -p workspace/unity`)
5. 내용을 사용자에게 출력합니다

```markdown

날짜: YYYY-MM-DD

## 요약

(MonoBehaviour 생명주기, 이벤트 흐름, 메인 스레드↔소켓 스레드 경계)

## Unity 특이사항
(Update/FixedUpdate 사용, Physics2D, Coroutine/async, 씬 전환 등)

## 서버 연동 분석
(프로토콜 메시지 흐름, 직렬화, KeepAlive 처리)

## 주요 발견
- 잠재적 문제, 의도적 트레이드오프, 개선 여지

## 관련 파일
| 파일 | 역할 |
|------|------|
```

## 구현 모드

`.claude/myplan/` 에서 `unity_` 키워드가 포함된 계획서를 우선 선택합니다.  
인자가 있으면 키워드 일치 계획서를 사용하고, 없으면 가장 최근 unity 계획서를 사용합니다.  
계획서를 찾지 못하면 사용자에게 `/unity 계획` 으로 먼저 계획을 세워달라고 안내하고 종료합니다.

### 진행 순서

1. 계획서를 로드하고 사용자에게 출력합니다
2. **미결 질문** 항목이 있으면 구현 전에 사용자에게 답을 요청합니다
3. 계획서의 "단계별 작업 계획"을 순서대로 실행합니다
4. `Client/World/Assets/` 하위 파일만 생성·수정합니다 (서버 코드 변경 시 사용자 승인 필수)
5. 각 단계 완료 후 한 줄로 진행 상황을 알립니다
6. 완료 후 아래 형식으로 보고합니다

```
## 구현 완료

사용한 계획서: .claude/myplan/YYYYMMDD_unity_xxx.md

### 변경된 파일 (Client/World/Assets/ 기준)
- 파일명: 변경 내용 요약

### 계획 대비 변경 사항
- (없으면 "계획대로 구현")

### 빌드/컴파일 주의사항
- Unity Editor에서 확인이 필요한 사항
```

**제약**: 계획에 없는 파일은 수정하지 않습니다. 서버 코드(`Server/`, `Library/`, `Scripts/`) 변경은 반드시 사용자 승인 후 진행합니다.

## 리뷰 모드

코드를 수정하거나 생성하지 않습니다. 오직 읽고 리뷰합니다.

### 진행 순서

1. 인자로 지정된 파일/컴포넌트를 리뷰합니다. 없으면 최근 변경 파일을 대상으로 합니다
2. 관련 MonoBehaviour, 인터페이스, 서버 핸들러를 함께 읽습니다
3. 아래 형식으로 리뷰 결과를 작성합니다
4. `workspace/unity/` 에 `YYYYMMDD_unity_<대상요약>.md` 로 저장합니다 (Bash: `mkdir -p workspace/unity`)
5. 내용을 사용자에게 출력합니다

```markdown
# Unity 코드 리뷰: [대상 요약]

## 총평

## 리뷰 대상

| null 체크 (오브젝트 파괴 후 접근) | ✅/⚠️/❌ | |
| 코루틴 누수 없음 | ✅/⚠️/❌ | |
| 서버 연동 KeepAlive 처리 | ✅/⚠️/❌ | |
```

## 공통 제약사항

- `Client/World/Library/` (Unity 캐시) 는 읽지 않습니다
- `Client/World/Assets/TextMesh Pro/` 는 서드파티이므로 수정하지 않습니다
- Unity API는 반드시 메인 스레드에서 호출합니다 (소켓 콜백에서 직접 호출 금지)
- 코드에서 확인되지 않은 내용은 추측하지 않고 "확인 필요"로 명시합니다
